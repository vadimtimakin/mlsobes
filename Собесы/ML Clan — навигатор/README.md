# Как устроен навигатор ML Clan

## Что считается источником

- Источник встречаемости вопроса — интервью из `ML Clan Export`.
- Текстовые сообщения, аудио, видео и OCR после извлечения текста являются одной сущностью — интервью.
- Существующие Markdown-пулы задают нормализованную формулировку и тему вопроса, но не являются вторым каталогом интервью.
- Скрины и продолжения одного собеседования объединяются в один `interview_id`, поэтому не раздувают частоту.

## Как пользоваться

Открой [[ML Clan — навигатор]] и нажми готовый пресет либо выставь фильтры:

- `Все банки` — все вопросы из банковских и финтех-интервью;
- `Банки без LLM/NLP/CV/RecSys` — тот же сектор, но специализированные вопросы скрыты на уровне вопроса;
- `Только Сбер` — интервью Сбера без удаления смешанных доменов;
- `Classic ML` — все компании, но без LLM/NLP/CV/RecSys/Ranking/Search/Deep Learning.
- `Лайвкодинг` — отдельный подтверждённый срез практических задач из топика «Собеседования».

Сортировка по умолчанию:

1. количество разных компаний, где встретился вопрос;
2. количество разных интервью внутри текущих фильтров;
3. дата самого свежего интервью.

При выборе одной компании первый критерий у всех одинаков, поэтому фактически вопросы идут по числу её интервью и свежести.

## Дедупликация

Генератор автоматически объединяет только полностью одинаковый нормализованный текст. Похожие по смыслу вопросы не склеиваются. После ручной проверки Codex добавляет подтверждённые объединения в `config/manual-deduplication.json`.

## Обновление данных

Для просмотра генератор не нужен: готовые данные уже лежат в `data/navigator-data.json`.

Для обновления нужен Python и исходный экспорт `ML Clan Export`. Открой терминал в папке `ML Clan — навигатор` и запусти (укажи свой путь к экспорту):

```powershell
python "scripts/build_navigator.py" --export-root "/путь/к/ML Clan Export"
```

Проверка, что JSON актуален:

```powershell
python "scripts/build_navigator.py" --export-root "/путь/к/ML Clan Export" --check
```

Компания и сектор размечены для каждого используемого source ID. Отдел и этап намеренно опциональны и заполнены только там, где это можно уверенно восстановить из сообщения или транскрипта.
